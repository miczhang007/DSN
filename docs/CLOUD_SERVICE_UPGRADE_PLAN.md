# 桌面便签云服务版方案

> 状态：定稿（2026-11-06）
> 适用范围：本地版 v1.5.1 开源冻结后的私有客户端、Cloud API、用户 Web、管理后台与移动端。
> 本文替代此前版本，作为云服务版产品与技术方案的唯一基线。

---

## 1. 背景与边界

### 1.1 已确认的产品决策

1. 本地版 v1.5.1 是最后一个开源版本；公开仓库冻结并归档，后续单机版更新转入私有仓库。
2. 本地功能永久免费、无需登录、可完全离线使用；云同步是独立的可选订阅。
3. 云同步默认自动执行，同时提供手动「立即同步」入口。
4. 移动端以本地操作为主，不做移动 Web 版；APP / 小程序选型待定，但均不改变云端数据库路线。
5. 冲突默认由系统自动裁决，尽量减少人工处理；无法安全自动裁决的情况保留记录，但不打断日常使用。

### 1.2 不变原则

- 客户端本地 SQLite 是用户真实数据源，云端不是本地操作的前置依赖。
- 本地操作成功的标准是本地事务提交成功，不等待网络或服务端响应。
- 无网络、服务维护、鉴权失效、订阅到期都不影响既有本地任务、节点、历史与设置。
- 云端账号是独立身份；本地 `owner`（分类名）只作为数据归属与展示字段，不能作为云端身份或鉴权依据。
- 同步只传版本化操作，不传 SQLite 文件、SQL、整表覆盖数据。
- 公共客户端仓库不得依赖私有仓库构建，也不得包含生产密钥、数据库连接串、管理接口或内部运营信息。

## 3. 账号与设备体系

### 3.1 云账号

- 主身份使用邮箱账号；后续可扩展手机号。
- 第三方登录通过 `auth_identities` 表绑定，不作为账号主键：
  - 微信小程序 `openid` / `unionid`
  - Apple / Google OAuth
  - 邮箱验证码或密码
- PC 登录采用系统浏览器 OAuth 2.1 Authorization Code + PKCE，客户端不长期保存密码。
- APP 使用同样的 OAuth PKCE；小程序通过 `wx.login` 获取微信身份后绑定到已有云账号。
- Access Token 短时有效，Refresh Token 轮换、可撤销，保存在系统安全凭据库：
  - Windows：Credential Manager
  - iOS：Keychain
  - Android：Keystore

### 3.2 绑定关系

- 用户首次开启云同步时，显式选择要同步的本地分类与数据范围。
- 禁止默认上传全部本地数据；禁止把本地 `owner`/分类名直接作为云账号。
- 每个云账号首期只有一个 `personal` space；`spaces` / `space_members` 预留未来共享空间。
- 设备为安装实例 UUID；服务端根据令牌解析账户与设备，不信任客户端传入的账户、空间或“已订阅”标记。

### 3.3 退出与注销

- 退出登录或解绑设备：停止同步，本地数据完整保留。
- 云端账号注销：立即撤销会话并停止同步，建议 30 天可撤销宽限期后删除云端数据。
- 本地数据删除与云端账号删除是两件独立操作。
- 订阅取消/到期：停止云同步，保留本地数据与待同步队列。

## 4. 同步数据范围

| 数据 | 是否同步 | 说明 |
| --- | --- | --- |
| 分类 | 是 | 新增云端 `categories` 实体（UUID、名称、排序） |
| 任务 | 是 | 标题、分类、紧急、开始时间、状态字段、排序 |
| 任务节点 | 是 | 增加跨端 `sync_id`，本地自增 ID 仅作本地键 |
| 生命周期/进度事件 | 是 | 追加型事件，增加跨端 `sync_id` |
| 周期任务规则 | 是 | 所属分类、频率、生成时间、状态等 |
| 手工排序 | 是 | 作为任务列表排序操作同步 |
| 主题、字体、便签大小 | 否（首期） | 各端展示差异大，保留设备本地 |
| 签名 | 可选 | 可作为账号资料后续同步 |
| 开机自启动、窗口位置 | 否 | 系统级/设备级设置 |

### 4.1 分类实体化

当前分类仅保存在客户端 localStorage，无法跨设备/移动端恢复。云端同步前必须升级为独立实体：

- 本地新增 `categories` 表（UUID、名称、排序）；
- 任务保留 `owner` 兼容展示，同时增加 `category_id`；
- 云端使用分类实体同步；
- 分类重命名操作同步到分类实体，任务按 `category_id` 关联。

### 4.2 跨端 ID

- 任务 ID 已是 UUID，直接作为跨端实体 ID。
- 节点、生命周期事件新增不可变 `sync_id UUID`。
- 本地排序、展示可继续使用本地自增 ID。
- 所有跨端实体的删除使用墓碑，不使用物理删除直接覆盖。

## 5. 总体架构

```text
桌面客户端（Tauri + Vue + Rust）
  → 本地 SQLite 业务表
  → 同事务写入 sync_outbox
  → 后台同步服务
  → HTTPS Cloud API
  → PostgreSQL

移动端（APP / 小程序）
  → 本地 SQLite 或本地缓存 + outbox
  → 同一版本化 API
```

### 5.1 客户端本地层

- 现有业务表继续服务本地查询与 UI。
- 新增本地表：

| 表 | 用途 |
| --- | --- |
| `sync_outbox` | 未获服务端确认的本地同步操作 |
| `sync_state` | 设备、空间、游标、最后成功同步时间与状态 |
| `sync_inbox_applied` | 已合并的远端操作，保证重复拉取幂等 |
| `sync_tombstones` | 删除墓碑，防止旧数据复活 |
| `sync_conflicts` | 无法自动裁决的冲突证据与处理结果 |

- 本地写入硬性要求：业务写入与 `sync_outbox` 操作必须在同一个 SQLite 事务中完成；事务提交后才向 UI 返回成功。
- 任何情况下不得出现“本地已修改但没有待上传操作”的状态。

### 5.2 同步闭环

```text
本地操作
  → 业务写入 + outbox 入队（同一事务）
  → 后台 push（批量 ≤ 50 条）
  → 服务端按 operation_id 幂等写入操作日志、更新投影
  → 返回 operation_id + sequence
  → 客户端标记 outbox 完成
  → pull 游标后的远端增量
  → 本地事务合并
```

### 5.3 自动与手动同步

自动触发时机：

- 应用启动；
- 网络恢复；
- 应用恢复/前台恢复；
- 本地数据变更后（短暂合并延迟）；
- 定时检查；
- 用户手动点击「立即同步」。

失败重试使用指数退避（5 秒、30 秒、2 分钟、10 分钟、30 分钟）。只有收到服务端明确确认，才能从 outbox 移除操作。

状态展示应低频，默认只显示「已同步 / 离线 X 项待同步 / 需要重新登录」；长期积压、令牌失效、本地写入失败才作明显提示。

## 6. 云端数据库

### 6.1 技术选型

- 云端数据库使用 **PostgreSQL 15+**。
- 客户端本地继续使用 **SQLite**；移动端 APP 使用 SQLite（Room / SQLDelight / GRDB / Drift 等）。
- 小程序没有原生 SQLite，使用本地 KV 缓存或经评估的 Wasm SQLite；不能依赖完整 SQLite 能力。
- 客户端与云端兼容性靠统一实体模型、UUID、版本化协议和 OpenAPI，不共用数据库引擎。

### 6.2 核心表

```text
accounts / auth_identities / devices / subscriptions
spaces / space_members
categories
tasks / task_milestones / task_events
recurring_task_settings
sync_operations          -- 不可变操作日志
sync_entity_projections  -- 当前可查询投影
sync_snapshots           -- 游标过期后的快照
sync_conflicts           -- 自动裁决证据
```

- 业务实体使用 UUID 与 `TIMESTAMPTZ`。
- `sync_operations` 以 `(space_id, operation_id)` 唯一约束保证幂等，并以服务端递增 `sequence` 作为拉取游标。
- 删除墓碑至少保留 90 天；超过保留期且安全确认后才清理。
- 需要支持用户 Web / 管理后台查询时，核心业务使用规范化读模型；不建议只依赖通用 JSONB 投影。
- 客户端不允许直接连接 PostgreSQL，也不允许上传/下载数据库文件。

## 7. 同步协议

### 7.1 操作模型

```json
{
  "id": "operation-uuid",
  "schemaVersion": 1,
  "entityType": "task",
  "entityId": "task-uuid",
  "operationType": "upsert",
  "deviceId": "device-uuid",
  "clientHlc": "2026-11-06T09:30:00.000Z|0001|device-uuid",
  "changedFields": {
    "title": "准备云同步方案",
    "categoryId": "category-uuid"
  }
}
```

### 7.2 API

- `POST /v1/sync/push`：批量上传操作，按 `operation_id` 幂等确认。
- `GET /v1/sync/pull`：按空间游标增量拉取。
- `GET /v1/sync/snapshots/{id}`：游标过期时获取快照，快照校验通过后与本地未确认 outbox 合并。
- 账号、设备、订阅、用户 Web 与后台管理接口使用独立路由并分别鉴权。
- 私有云仓库中的 OpenAPI 是唯一权威；PC、Web、移动端依赖发布的兼容版本，不手写复制契约。

### 7.3 版本兼容

- 只做向后兼容的新增字段；不兼容变更升级主版本并保留迁移期。
- 移动端发布周期慢，服务端必须至少兼容当前大版本及上一个客户端版本。
- 公开客户端只获取公开 API 子集；管理端与内部接口不进入公开客户端。

## 8. 冲突默认策略

| 场景 | 系统默认处理 |
| --- | --- |
| 不同设备新增任务、节点、进度 | 按 UUID 追加，全部保留 |
| 同一任务不同字段修改 | 字段级合并 |
| 同一字段并发修改 | HLC 较新者胜出；相同 HLC 用设备 ID 决胜 |
| 节点/生命周期事件并发追加 | 按 `sync_id` 幂等追加 |
| 并发手工排序 | 以较新的整表排序操作为准 |
| 删除与编辑并发 | 删除墓碑优先，防止复活 |
| 删除与明显更新并发 | 墓碑优先，写入 `sync_conflicts` 保留证据 |
| 周期规则并发编辑 | 字段级 HLC；删除用墓碑 |
| 分类并发改名/排序 | 字段级 HLC；排序以较新列表操作为准 |

执行原则：

- 默认不弹冲突选择框，不打断用户。
- 冲突记录只用于追溯，不要求每次处理。
- MVP 不做冲突处理页；后续可增加「异常记录」入口，用于恢复或复制为副本。
- 不允许静默丢失数据；无法自动裁决时必须保留另一版本证据。

## 9. 移动端路线

移动端目前待选型，数据库路线不受影响，但本地能力不同：

| 维度 | APP | 小程序 |
| --- | --- | --- |
| 云端数据库 | PostgreSQL，不变 | PostgreSQL，不变 |
| 本地存储 | SQLite，稳定 | 本地 KV；Wasm SQLite 需额外验证 |
| 离线能力 | 完整 | 轻量；容量和生命周期受限 |
| 自动/后台同步 | 系统后台/推送配合 | 主要靠启动、前台恢复、手动 |
| 账号 | 邮箱/OAuth/Apple/Google | 微信 `openid` / `unionid`，需绑定云账号 |
| 支付 | App Store / Google Play IAP | 微信支付 |
| 建议定位 | 本地优先主客户端 | 微信内轻量入口/轻客户端 |

推荐路线：

1. 先完成 Windows 同步闭环与稳定 API；
2. 移动端优先做 APP，保证本地优先与离线可靠性；
3. 小程序作为后续轻量入口，本地层按「缓存 + outbox」设计，不按完整 SQLite 设计；
4. 移动端开发前先做同步协议和本地数据层技术验证。

## 10. 鉴权、订阅与合规

### 10.1 鉴权

- OAuth 2.1 Authorization Code + PKCE。
- Access Token 短时有效，Refresh Token 轮换并可撤销。
- 服务端从令牌解析账户、设备、空间和订阅权益，不信任客户端传入的身份字段。
- 登录失败保护、速率限制、设备会话管理、令牌吊销。

### 10.2 订阅

- 云同步是订阅权益；本地功能永久免费。
- 订阅只控制云端上传/下载权益，不锁定本地功能，不删除本地数据。
- 订阅到期停止同步，保留本地数据与待同步操作。
- 支付渠道按阶段接入；服务端权益为唯一判断依据，客户端显示不代表授权结果。

### 10.3 用户 Web 与管理后台

- 用户 Web：官网/下载、账号、订阅、设备、云端数据导出与删除；不做任务编辑 Web。
- 管理后台：用户、订阅、审计、客服与运营；独立域名、独立身份、强制 MFA，VPN/ IP 白名单。
- 管理接口不得出现在公开客户端或公开 API 文档中。

### 10.4 合规底线

- HTTPS、静态数据和备份加密；密码使用 Argon2id 或 bcrypt。
- 每日全量备份与持续日志归档，支持时间点恢复；定期恢复演练。
- 上线前完成云同步服务协议、云端隐私政策、账户注销与数据删除规则、数据安全说明、订阅/退款/支付说明。
- 真实云账户、订阅与云数据上线前确定公司主体、数据区域与备案要求。

## 11. 当前实现状态

### 11.1 已有基础

私有 `sticky-note-cloud-api` 已具备同步底座：

- Fastify + Node.js + PostgreSQL；
- 迁移已包含 accounts、spaces、devices、`sync_operations`、`sync_entity_projections`、`sync_snapshots`；
- OpenAPI v1 已包含 `/v1/sync/push`、`/v1/sync/pull`、`/v1/sync/snapshots/{id}`、`/healthz`、`/readyz`；
- 服务端按 `operation_id` 幂等，操作日志按 sequence 增量拉取，删除墓碑优先；
- 现有投影使用 HLC LWW。

### 11.2 关键缺口

1. 认证仍是开发环境固定 Token，没有 OAuth 2.1 / JWT 验签，不能公网部署。
2. 没有订阅、权益校验、用户 Web、管理后台。
3. Windows 客户端没有 `sync_outbox`、`sync_state`、`sync_inbox_applied`、`sync_tombstones`、`sync_conflicts`，节点/事件也缺少 `sync_id`。
4. 分类尚未成为云端实体。
5. 服务端当前为整 payload LWW，尚未实现任务字段级合并与冲突记录。
6. 没有移动端项目。
7. 没有生产部署、备份监控、协议与注销流程。

## 12. 分期与验收

### 12.1 阶段

1. **方案与契约定稿**：补齐分类实体、字段级 HLC、同步协议、账号模型。
2. **Windows 同步闭环**：本地迁移、outbox、设备绑定、两台 PC 的自动/手动同步、离线补传、幂等、快照、冲突记录。
3. **生产账号与订阅**：OAuth/JWT、邮箱验证、找回密码、设备管理、权益服务。
4. **用户 Web 与合规**：账号、订阅、设备、数据导出/删除、协议与隐私。
5. **移动端**：APP 优先做技术验证，再决定是否补小程序轻客户端。
6. **稳态增强**：冲突记录查看、备份恢复演练、监控、客服与审计。

### 12.2 MVP 验收

- 两台 Windows PC 交替离线/联网：新建、编辑、完成、撤销、节点、进度、分类、周期规则、手工排序可收敛。
- 重复请求不重复写入；服务端按 `operation_id` 幂等。
- 云端停机期间本地持续可用；恢复后自动补偿。
- 订阅到期不影响本地功能与数据。
- 无法自动裁决的冲突可追溯，不静默丢失数据。
- 用户可导出云端数据、注销账号并清理云端数据。
