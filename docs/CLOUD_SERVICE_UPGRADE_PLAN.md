# 桌面便签云服务版产品改造方案

> 状态：方案基线（2026-08-24）  
> 适用范围：在不改变现有 Tauri + Vue + SQLite 本地优先架构的前提下，为桌面便签增加可订阅的云同步能力。

## 1. 改造目标与边界

### 1.1 产品目标

1. 保持基础版免费、开源、无需登录且可完全离线使用。
2. 云同步作为独立可选订阅服务；订阅后支持多台 Windows PC 自动同步，后续平滑扩展至移动端与其他操作系统。
3. 同步尽量后台自动完成，避免要求用户手动上传、下载或处理常规网络波动。
4. 提供完整的云账户开通、登录鉴权、找回密码、设备管理、订阅、账户注销和数据删除能力。
5. 云端服务、账号与订阅运营保持私有；Windows 客户端继续在现有 MIT 开源仓库维护。

### 1.2 不变原则

* 本地 SQLite 始终是客户端真实数据源；云端不是客户端操作的前置依赖。
* 本地操作成功的标准是本地事务提交成功，不等待网络或服务端响应。
* 无网络、服务维护、鉴权失效、订阅到期都不影响既有本地任务、节点、历史、设置的使用。
* 云端账号是独立身份；当前 `owner` 仅保留为本地用户/数据归属兼容信息，不能作为云端身份。

## 2. 项目与部署边界

```text
miczhang007/DSN                  Windows 客户端，继续 MIT 开源
sticky-note-cloud-api            私有：账号、订阅、同步 API、后台任务、OpenAPI
sticky-note-web                  用户 Web：官网宣传 + 登录后跨端服务门户
sticky-note-admin-web            私有：内部运营管理后台
sticky-note-mobile               后续独立：iOS / Android 客户端
```

### 2.1 各项目职责

| 项目 | 职责 | 部署边界 |
| --- | --- | --- |
| Windows 客户端 | 本地任务管理、SQLite、离线队列、云同步客户端、登录入口 | 用户 Windows PC |
| Cloud API | 账号、令牌、订阅权益、同步、邮件、数据清理、OpenAPI | 私有服务网络 |
| User Web | 官网、下载、价格、协议；注册、登录、账户、设备、账单、数据管理 | `www` / `app` 域名 |
| Admin Web | 用户、订阅、审计、客服与运营 | 独立管理域名，MFA + VPN/IP 限制 |
| Mobile | 本地数据库、离线使用、移动同步与商店订阅适配 | iOS / Android |

用户 Web 的公开官网与登录后服务区可作为一个工程维护；管理后台独立工程。Cloud API 不承载 Web 前端工程。静态 Web 可部署至 CDN/对象存储，API、Worker 与数据库部署在私网；API 是所有客户端唯一服务端权威。

## 3. 客户端架构与本地数据库演进

```text
Vue 界面
  → Tauri 命令 / 本地业务层
  → SQLite 业务数据 + 同事务 sync_outbox
  → 后台同步服务（上传、拉取、合并、重试）
  → HTTPS Cloud API
```

Rust 端后续按职责逐步拆分为 `local`（迁移、仓储）、`sync`（队列、API、合并、冲突、调度）及 `commands`（Tauri 接口）。无需一次性重构现有业务功能。

### 3.1 本地数据兼容

现有表 `tasks`、`task_events`、`task_milestones` 继续服务本地查询和 UI。历史数据迁移时：

* `tasks.id` 已是 UUID，保持为跨端任务 ID。
* `task_milestones.id` 和 `task_events.id` 的本地自增 ID 保留作本地键；新增不可变 `sync_id UUID` 作为跨端实体 ID。
* 新增 `device_id`（安装实例级 UUID），凭据与 Refresh Token 存入 Windows Credential Manager，禁止明文落入 SQLite。
* 为已启用云服务的数据空间新增 `cloud_account_binding`，绑定本地用户、云账户和云端个人空间；用户必须显式选择要绑定的本地用户，禁止默认上传所有本地用户数据。

建议新增表：

| 表 | 用途 |
| --- | --- |
| `sync_outbox` | 未获服务端确认的本地同步操作 |
| `sync_state` | 设备、空间、游标、最后成功同步时间与状态 |
| `sync_inbox_applied` | 已合并的远端操作，确保重复拉取幂等 |
| `sync_tombstones` | 删除墓碑，防止旧数据复活 |
| `sync_conflicts` | 无法自动裁决的冲突证据和处理结果 |

### 3.2 每次本地写入的硬性要求

在同一个 SQLite 事务中：

1. 写入任务、节点、事件或排序变更；
2. 生成带 `operation_id`、`device_id`、`client_hlc` 和 `schema_version` 的同步操作；
3. 写入 `sync_outbox`。

事务提交后即可向 UI 返回成功，并异步请求同步。任何失败不得出现“数据已修改但没有可补传操作”的状态。

## 4. 云端数据与同步协议

### 4.1 云端数据库

首期使用 PostgreSQL，按账户、业务投影、同步日志分层。核心表如下：

```text
accounts / devices / subscriptions
spaces / space_members
tasks / task_milestones / task_events
sync_operations / sync_cursors / sync_conflicts
```

每个云账户首期有一个 `personal` space；`spaces` 和 `space_members` 预留未来共享/团队空间。业务表使用 UUID 与 `TIMESTAMPTZ`，保存当前可查询投影；`sync_operations` 保存不可变、幂等的增量操作日志，并以服务端递增 `sequence` 作为拉取游标。

同步不传 SQLite 文件、SQL 或全表覆盖数据，只传版本化操作。例如：

```json
{
  "id": "operation-uuid",
  "schemaVersion": 1,
  "entityType": "task",
  "entityId": "task-uuid",
  "operationType": "upsert",
  "clientHlc": "2026-08-24T15:34:00.000Z-DEVICE_A",
  "payload": {
    "changedFields": { "title": "准备云同步方案" }
  }
}
```

Cloud API 项目的 `openapi/` 是唯一协议权威。API 发布时生成版本化 OpenAPI 文件、TypeScript SDK 和未来移动端需要的 SDK/模型；客户端固定依赖已发布版本。兼容性优先增加可选字段；删除字段、变更语义或冲突规则时升级主版本并提供迁移期。

### 4.2 鉴权与权益

* 登录采用系统浏览器的 OAuth 2.1 Authorization Code + PKCE；桌面端不长期保存密码。
* Access Token 短时有效，Refresh Token 轮换、可撤销，并保存在系统安全凭据库。
* 服务端从令牌解析账户和设备，检查空间成员关系、设备状态和订阅权益；不信任客户端传入的 `account_id`、`owner` 或“已订阅”标记。
* 订阅只控制云端同步权益；到期后停止远端上传/下载，不得锁定本地功能或删除本地数据。

## 5. 自动同步、离线补偿与云端异常

### 5.1 自动机制

以下时机后台触发：应用启动、网络恢复、应用恢复、本地数据变更、定时检查及用户主动点击“立即同步”。本地变更后采用短暂合并延迟，减少零散请求；每次上传使用小批量（例如 50 条）操作。

```text
本地操作 → SQLite 业务写入 + outbox 入队 → 后台 push
                                          ↓
                                  服务端确认后标记完成
                                          ↓
                                pull 远端增量 → 本地合并
```

网络错误与服务端可重试错误使用指数退避（如 5 秒、30 秒、2 分钟、10 分钟，最长 30 分钟）；网络恢复可立即重试。服务端超时/无响应时一律保留 outbox，只有收到含 `operation_id` 的明确确认后才标记已同步。服务端按 `operation_id` 去重，重复上传不得产生重复任务或事件。

### 5.2 服务异常时的体验

| 场景 | 客户端行为 |
| --- | --- |
| 无网络 | 继续本地使用，显示“离线，X 项待同步” |
| 服务暂不可用/维护 | 自动重试，提示“本机数据已安全保存” |
| 令牌失效 | 暂停同步并提示重新登录；本地可继续使用 |
| 订阅到期 | 停止云同步；本地数据和待同步记录保留 |
| 本地库写入失败/空间不足 | 阻止可能丢失数据的写操作，明确提示恢复或备份 |

常规状态仅显示在菜单/状态区；待同步超过 7 天、需重新登录、本地写入失败、无法自动裁决冲突时才作显著提示。

### 5.3 异常恢复顺序

云端恢复或客户端重新联网后：

1. 刷新令牌与订阅权益；
2. 拉取本地游标后的远端增量并在本地事务中合并；
3. 上传本机尚未确认的 outbox 操作；
4. 再拉取一次增量，确认视图收敛；
5. 更新最后成功同步时间。

若游标过期，执行“下载快照 + 合并本地未确认操作”，禁止用云端快照直接覆盖本地库。

## 6. 冲突与删除规则

同步版本使用 HLC（混合逻辑时钟：时间、逻辑计数、设备 ID），不依赖不可靠的客户端 `updated_at`。

| 场景 | 规则 |
| --- | --- |
| 不同设备新增任务、节点或进度 | 按 UUID 追加合并，全部保留 |
| 同一任务的不同字段变更 | 字段级合并 |
| 同一字段并发修改 | HLC 确定性最后写入优先，并保留审计依据 |
| 节点/生命周期/进度并发追加 | 追加合并、幂等去重 |
| 并发排序 | 使用 `sort_key`；以较新排序操作为准 |
| 删除与旧编辑并发 | 删除墓碑优先，避免数据复活 |
| 删除与明显更新版本并发 | 记录到 `sync_conflicts`，不静默丢弃 |

删除采用带版本的墓碑，云端和本地至少保留 90 天；只有超过保留期且满足安全确认条件后才物理清理。对于无法安全裁决的冲突，保留当前自动裁决版本及另一版本证据；用户可保留本机、保留云端或复制为新任务，选择本身将生成新的同步操作。

## 7. 账号、订阅与合规

### 7.1 用户功能

* 开通与订阅：云同步权益由服务端统一判断，未来可对接 Web、Apple、Google 等支付来源。
* 账户：注册、邮箱验证、登录、退出、修改密码、找回密码、设备会话管理。
* 注销：二次确认和密码/邮箱验证，立即撤销会话并停止同步；建议 30 天可撤销宽限期后清除云端账号数据。账户注销、本地数据删除和取消订阅是三个独立操作。
* 取消/到期：停止云同步但保留本机数据；提供数据导出和云端数据管理能力。

### 7.2 安全与灾备底线

* HTTPS、静态数据和备份加密；密码使用 Argon2id 或 bcrypt 哈希。
* 速率限制、登录失败保护、操作审计、令牌吊销、依赖/密钥扫描。
* 管理后台独立身份体系，强制 MFA，使用 VPN 或 IP 白名单；服务端也必须校验管理权限。
* PostgreSQL 做高可用或快速恢复；每日全量备份与持续日志归档，支持时间点恢复；定期恢复演练。
* 同步日志留存时间应长于支持的最大离线窗口；维护时返回明确可重试错误码并提供状态页。

### 7.3 上线前必须形成的文档

* 云同步服务协议；
* 云端隐私政策；
* 账户注销与数据删除规则；
* 数据安全与备份说明；
* 订阅、退款及第三方支付说明；
* 官方服务与商标使用声明。

现有本地版的 `PRIVACY.md` 不得直接替代云端隐私政策。真实云账户、订阅、支付和云数据上线前，建议由公司作为服务与数据处理主体；公司成立后以书面协议完成个人既有代码、域名、品牌等知识产权的转让或独占许可。

## 8. 开源与商业边界

Windows 客户端继续使用 MIT。MIT 覆盖客户端代码，不要求公开云端实现，也不授予官方品牌、域名、订阅权益、云资源或运营系统的权利。

公开客户端可以包含公开 API 域名、OpenAPI 客户端模型、同步算法、登录 PKCE 流程和用户可见套餐信息；不得包含：生产密钥、数据库连接串、JWT/加密密钥、支付私钥及验签密钥、管理 API、内部监控地址、风控阈值、运营规则或用户数据。安全边界必须在服务端鉴权、密钥管理和数据访问控制中实现，不能依赖客户端代码不公开。

## 9. 分期实施与验收

1. **同步底座**：本地迁移、UUID、设备 ID、outbox/inbox/state/tombstone、同步状态展示、OpenAPI 基线与端到端测试样例。
2. **Windows 同步闭环**：账号登录、权益校验、两台 Windows PC 的自动同步、离线补传、幂等和冲突记录。
3. **订阅与合规上线**：用户 Web、订阅、找回密码、设备管理、注销、协议与隐私文档、监控和灾备。
4. **稳态增强**：冲突处理页、导出、备份恢复演练、客服与审计能力。
5. **跨平台**：移动端独立接入同一版本化 API；优先复用同步规则与本地优先原则，不依赖 Windows 数据库实现。

Windows 首期验收必须覆盖：两台设备交替离线/联网下的新建、编辑、完成、撤销、节点与进度变更；重复请求不重复写入；云端停机期间本地持续可用；恢复后自动收敛；订阅到期不影响本地；无法自动裁决时可追溯且不静默丢数据。
